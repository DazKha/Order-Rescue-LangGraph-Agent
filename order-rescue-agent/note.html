Trạng thái hiện tại

Mục tiêu

Agent xử lý các case giao hàng thất bại tổng hợp, hỏi làm rõ khi cần, đánh giá lại sau event và đưa recommendation qua policy gate.

Hai decision point

LLM gọi ở INITIAL và AFTER_EVENT. Assessment sau event được dùng lại, không gọi lần thứ ba.

Giao tiếp

Chỉ là event mô phỏng trong CLI/checkpoint. Không nhắn buyer thật, không gọi carrier, không dispatch.

Case mẫu

OR-001: giao thất bại vì người nhận ở cơ quan; hiện còn cơ hội hỏi intent/khả năng nhận hàng.

Nguyên tắc chốt: LLM đánh giá, hỏi và đề xuất; validation, eligibility, contact policy, recovery policy và final status do code deterministic quyết định. Recommendation luôn executed=False.

Input / output contracts

Đầu vào

  • BiCaseInput: các field case nhìn thấy từ BI như status/reason, service/route, attempts, contact evidence, return state, deadline, disruption, actor role và extra context.
  • DeliveryContext: normalized delivery status, courier note, attempt bounds, return state, contact eligibility và buyer intent.
  • CaseEvent: event tới sau interrupt, ví dụ BUYER_REPLY, NO_REPLY, TIMEOUT, SELLER_UPDATE hoặc DISRUPTION_RESOLVED.
  • Evidence: ID + kind + value + provenance + timestamp + raw_text tùy chọn. Evidence refs từ model phải tồn tại trong pack hiện tại.

LLM output: AgentDecision

  • INITIAL: assessment + route; ASK cần target và information_request; WAIT cần target; PROPOSE_RECOVERY cần action candidate và rationale.
  • AFTER_EVENT: parsed buyer intent/facts + updated assessment + action candidate; route bắt buộc là PROPOSE_RECOVERY.
  • Enums cho hypothesis, confidence, intent, route, target và action được validate. Sau event, raw reply vẫn được lưu làm evidence; intent mơ hồ là UNKNOWN.

Đầu ra

  • Đang chờ event: case_status là WAITING_FOR_BUYER hoặc WAITING_FOR_EVENT; có information_request và checkpoint.
  • Đã kết thúc: final_recommendation gồm action, policy decision/version, rationale, executed=False và side_effects=[]; status là COMPLETED, BLOCKED hoặc ESCALATED.
  • events lưu lifecycle trace theo node, iteration và policy evaluation.

Chạy deterministic: python demo.py --auto. Chạy DeepSeek với event synthetic: python demo.py --auto --llm. Chạy tương tác: python demo.py --llm.

Giới hạn và nguyên tắc an toàn

  • Data và events synthetic; expected BI labels chỉ dành cho test, không vào prompt.
  • Policy demo/BI không phải policy vận hành đã được carrier xác nhận.
  • Không tool integrations, không external side effects và không production service/API.
  • Model timeout/JSON/schema/evidence failure không được silent fallback sang mock khi đã bật --llm.
  • Không lưu API key trong HTML/README, source, fixture hoặc commit. Note này chỉ ghi tên biến DEEPSEEK_API_KEY, không ghi giá trị.
  • React Observatory dùng mock riêng; npm run dev không nối vào agent Python.

Commands và vận hành local

cd order-rescue-agent
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# deterministic; auto-resume bằng fixture
python demo.py --auto

# tương tác; CLI chờ reply mô phỏng sau interrupt
python demo.py --llm

# DeepSeek ở cả hai decision points + event fixture
python demo.py --auto --llm

Nếu key nằm trong file `.env`, shell phải nạp file vào process trước khi chạy Python; chỉ đặt file trong thư mục không tự tạo environment variable. Không bao giờ echo/in ra giá trị key để debug. Kiểm tra an toàn: python -c 'import os; print("loaded" if os.getenv("DEEPSEEK_API_KEY") else "missing")'.

Test suite: python -m pytest -q. Test provider dùng fake transport; không cần gọi API thật.
